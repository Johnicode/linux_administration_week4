Setup & Storage

Server B was created in cPouta from a snapshot of Server A and given its own IP address. Server A still runs the original Week 2 counter and Week 3 report.

  • Server A: web files in /var/www/html, Flask app in /home/ubuntu/viikko2-app, backup script in /home/ubuntu/backup_www.sh (logs to backup.log).
  • Server B: backups stored outside web root in /var/backups/server-a/, read-only Flask app in /home/ubuntu/viikko2-app.

Users & Permissions

  • Linux: ubuntu runs the app and cron job. A separate backupuser on Server B receives files over SSH with a dedicated key. /var/backups/server-a/ is owned by backupuser:backupuser with chmod 700.
  • MariaDB: A dedicated replication user on Server A is limited to Server B's private IP. On Server B, the app uses ro_user@localhost with only SELECT privileges on viikko2.*, and read_only = 1 is enabled.

Backups & Replication

An hourly cron job on Server A (0 * * * * /home/ubuntu/backup_www.sh) packs /var/www/html into timestamped .tar.gz files and copies them to Server B via SCP.

-rw-rw-r-- 1 backupuser backupuser 1.2K Nov 20 14:00 www_backup_2026-11-20_14-00-01.tar.gz
-rw-rw-r-- 1 backupuser backupuser 1.2K Nov 20 15:00 www_backup_2026-11-20_15-00-01.tar.gz

MariaDB replicates continuously from Server A (server-id = 1) to Server B (server-id = 2). Replication does not replace historical backups, because accidental deletes or corrupted data on Server A are copied to Server B immediately.

Tests

  • Both /viikko2/ (Server A) and /viikko4/ (Server B) are publicly accessible.
  • Reloading Server A increments the counter and the new value appears on Server B after refresh (e.g. 71 -> 72).
  • Reloading Server B does not change the counter.
  • Two scheduled hourly backups (14:00 and 15:00) succeeded, and a test file restored to a temporary folder matched the original.
  • After rebooting Server B, the website, replication, and hourly backups kept working.

What I Learned

Because Server B was cloned from Server A, the Flask app and systemd service were already there. Instead of making a separate static page for /viikko4/, I pointed Nginx /viikko4/ to Gunicorn and put both the live counter and documentation in the same Flask template.
